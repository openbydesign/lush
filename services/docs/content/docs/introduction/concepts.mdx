---
title: Concepts
description: Core service and product concepts in Lush.
---

These concepts map to the main product surfaces, service boundaries, and shared
runtime responsibilities in Lush.

## API

Single entry point for apps and integrations.

The API keeps the product surface simple by authenticating requests, applying
cross-cutting policy, and routing work to the right backend boundary.

## Authentication & Authorization

Identity, sessions, organizations, roles, and access checks.

Authentication verifies users and issues sessions. Authorization evaluates what
an authenticated principal can do in an organization before protected actions
run.

## Sessions

Durable conversations and work contexts.

Sessions own messages and resumable interaction state so the same conversation
can move across desktop, web, mobile, and team chat. A session contains many
agent runs; it is not itself an execution process or security boundary.

## Managed Agents

Versioned definitions of instructions, model policy, tools, skills, memory, and
execution limits.

The built-in Lush assistant is the first managed agent. Organization policy
sets its capability ceiling, while a user's configuration may only narrow that
ceiling. Runs pin immutable agent and installation revisions so later edits do
not change in-flight or historical behavior.

## Agent Runs

One durable execution of an agent in a session, normally one user turn.

A run snapshots its effective configuration and capabilities and owns an
ordered event log, idempotency, cancellation, recovery, and terminal outcome.
Every first-party Chat turn is an agent run, even when it has no tools. Raw
programmatic inference calls outside Chat do not create runs.

## Agent Environments

The execution venue for one or more runs.

Run identity and execution venue are separate. Ordinary Chat uses an ephemeral
environment; Code can bind multiple runs to one session environment so its
workspace and harness state survive between turns. Capability-enabled runs
require an isolating provider. A local subprocess is a development execution
provider, not a production security boundary.

## Inference

Model routing across providers.

Inference owns provider selection, model pinning, failover behavior, and
request mediation across interchangeable model backends.

## Tools

Governed access to MCP, OpenAPI, and Lush-native capabilities.

A tool connection configures an integration and its credential mode; a tool
definition is one capability discovered from that connection; a tool call is
one attributable invocation by a run. Keeping them separate lets one
connection expose many independently governed tools.

The organization **Tool gateway** defines the available catalog and policy
ceiling. **My tools** holds a user's private connections and personal settings,
which may narrow but never expand organization policy. Models receive scoped
definitions and short-lived capabilities instead of raw URLs or credentials.

## Skills

Publish, resolve, and load agent skills.

Skills are the runtime layer for discovering and loading agent capabilities.
The shared skill catalog package keeps the reusable metadata primitives.

## Memory

Portable scoped memory across indexes.

Memory separates observed facts from derived memories and applies scoped access
controls across relational, graph, and vector-backed stores.

## Scheduler

Deferred actions, loops, and wakeups.

Scheduler owns durable timing for reminders, recurring loops, retry/backoff
state, and waking agents when work becomes due.

## Artifacts

Files, uploads, and generated work products.

Artifacts track durable outputs such as uploaded files, generated assets, code
results, storage references, and lifecycle policy.

## Team Chat

Slack, Teams, and Discord integration boundary.

Team Chat exposes Lush workflows inside collaboration platforms while keeping
platform-specific adapters behind one service interface.
